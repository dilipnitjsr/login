# DoD / Kite Connect Login

This Django application receives the Zerodha Kite Connect login callback, exchanges the short-lived `request_token` for a Kite `access_token`, and stores the access token for the authenticated Kite user.

## Security configuration

Production credentials must be supplied through environment variables. Do **not** put real values in Python files, templates, commits, screenshots, or logs.

Required variables:

- `KITE_API_KEY` — Kite Connect application API key.
- `KITE_API_SECRET` — Kite Connect application secret. Server-side only.
- `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST` — database holding `userKite`.
- `DB_PORT` — optional; defaults to `5432`.
- `DJANGO_SECRET_KEY` — preferred Django signing secret. `SECRET_KEY` is accepted for compatibility with the existing Heroku configuration.
- `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` — optional; login notifications are skipped when they are not configured.

Copy `.env.example` to `.env` for local development and fill in your own values. `.env` is ignored by Git.

## Important: rotate previously committed credentials

Earlier revisions of this repository contained credentials directly in source code. Removing them from the current branch does not invalidate copies in Git history. Before using this application again, rotate/revoke the affected credentials at their providers:

1. Kite Connect API secret (and API key if appropriate).
2. Telegram bot token.
3. Database password/user credentials.
4. Django secret key.

Do not reuse the old values.

## Authentication flow

1. The browser follows the login URL generated by `KiteConnect.login_url()`.
2. Zerodha authenticates the user.
3. Zerodha redirects to the registered application redirect URL with a short-lived `request_token`.
4. `hello.views.index` calls `generate_session(request_token, api_secret=...)`.
5. Kite returns session information including the `access_token`, `user_id`, and `user_name`.
6. The application updates `userKite.token` using a parameterized SQL query.
7. The application optionally sends a Telegram login notification.

The application never logs the request token or access token.

## Local setup

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# Export the values from .env using your preferred environment loader.

python manage.py migrate
python manage.py runserver
```

For Heroku or another hosting platform, configure the same variables in the platform's secret/configuration store rather than committing an `.env` file.

## Token storage note

The existing database schema stores the Kite access token in `userKite.token`. This patch preserves that format so existing consumers are not broken. If other services read this table directly, coordinate an application-wide migration before introducing encryption-at-rest for this field.
